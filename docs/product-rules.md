# 제품 및 권한 규칙

## 역할

- 질문자: 자신의 질문 수정, 해결 결과 등록, 조건을 충족한 전문가에게 수리 요청
- 일반 사용자: 공개 댓글과 비슷한 경험 등록, 도움 반응, 저장, 신고
- 인증 전문가: 공개 댓글, 추가 정보 요청, 안전 경고, 조건 충족 시 수리 요청 수신
- 관리자: 전문가 검증, 신고 처리, 계정 제재, 카테고리·브랜드·모델 정리

모든 댓글은 하나의 공개 대화에 시간순으로 나타난다. 댓글 작성 화면과 본문에는 `일반 의견`, `전문가 의견` 같은 유형을 두지 않고, 전문가 댓글도 별도 영역에 격리하지 않는다. 글쓴이 표시는 대화 맥락을 위해 제공하지만 댓글을 채택하거나 대표 답변으로 지정하지 않는다. 인증 여부와 권한 판정에 필요한 역할 정보는 내부 데이터로 보존할 수 있으며, 의견의 우열을 만드는 딱지로 사용하지 않는다.

## 회원가입과 로그인

- 공개 게시글과 댓글은 로그인하지 않아도 읽고 검색할 수 있다.
- 글쓰기, 댓글, 저장, 게시판 즐겨찾기처럼 계정에 남는 작업을 시작할 때 로그인으로 안내하고, 완료 뒤 사용자가 원래 보던 수리온 화면으로 돌려보낸다.
- 첫 출시의 기본 수단은 `카카오로 시작하기`와 `이메일 인증번호`다. 이메일 비밀번호를 새로 만들게 하지 않는다.
- 카카오와 이메일로 확인된 식별자는 로그인에 사용하고, 공개 화면에는 사용자가 정한 닉네임만 표시한다.
- 처음 인증한 사용자는 닉네임, 이용약관, 개인정보 수집·이용 동의, 만 14세 이상 확인을 마쳐야 가입이 완료된다. 프로필 사진과 마케팅 수신은 선택 사항이며 필수 동의와 묶지 않는다.
- 약관 동의에는 동의한 문서 종류와 버전, 동의 시각을 남긴다. 만 14세 미만 사용자의 법정대리인 동의 절차를 제공하기 전까지는 가입할 수 없도록 안내한다.
- 인증번호 전송 성공 여부를 이용해 가입된 이메일인지 추측할 수 없게 같은 수준의 안내를 사용하고, 인증번호 자체는 데이터베이스나 로그에 저장하지 않는다.
- 카카오·이메일 로그인은 동일한 사용자의 계정을 자동으로 합치지 않는다. 확인되지 않은 이메일 문자열만으로 계정을 연결하지 않으며, 추후 로그인된 상태의 본인 확인 절차로만 연결한다.
- 전문가도 일반 계정으로 시작한다. 실명, 연락처, 사업자 정보는 회원가입에서 받지 않고 별도의 전문가 신청에서 비공개로 수집한다.

### 로그인 후 복귀 주소

- 복귀 주소는 `/ask`, `/cases/...`처럼 `/` 하나로 시작하는 수리온 내부 경로만 허용한다.
- `https://...`, `//...`, 역슬래시가 섞인 값, 제어 문자, 파싱할 수 없는 값은 모두 `/my/questions`로 대체한다.
- OAuth 콜백의 `code`와 오류 값은 최종 화면 주소에 남기지 않는다.
- 로그인 버튼과 약관 링크를 눌러도 사용자가 입력한 안전한 복귀 주소는 유지한다.

## 전문가 댓글과 수리 요청

수리 요청은 다음 조건을 모두 만족해야 한다.

1. 요청자가 해당 질문의 작성자다.
2. 게시글이 해결 또는 미해결 종료 상태가 아니다.
3. 전문가는 개인 또는 사업자 인증을 받았고 수리 요청 수신을 켰다.
4. 해당 전문가가 그 글에 삭제되지 않은 유효한 댓글을 남겼다.
5. 같은 글에 대기 또는 수락 상태의 요청이 없다.

전화번호나 광고 문구만 남긴 댓글은 수리 요청 자격을 만드는 유효한 전문가 참여로 인정하지 않는다. 비공개 요청과 메시지는 요청자, 대상 전문가, 권한 있는 운영자만 접근한다.

## 해결 결과

해결 완료 여부는 글쓴이만 확정한다. 실제 원인, 해결 방법, 비용, 기간, 현재 작동 여부를 게시글의 해결 기록으로 남긴다. 해결 기록은 특정 댓글의 선택이나 채택과 독립적이며, 여러 사람의 의견을 참고했더라도 하나의 댓글을 대표 해답으로 지정하지 않는다. 해결되지 않은 경우에도 종료 이유를 기록해 반복적인 제안을 줄인다.

## 게시글 축적과 묶음

각 게시글은 한 사람의 질문 또는 경험으로 독립해 노출한다. 서비스가 임의의 글을 대표 사례로 승격하지 않으며, 같은 제품·모델·증상의 글이 많아지면 원문과 작성자를 유지한 채 탐색용 묶음으로 연결할 수 있다. 묶음은 개별 글을 대체하거나 합쳐 삭제하는 기능이 아니다.

## 게시판 선택

- 전체글, 검색, 글쓰기 등 게시판을 고르는 모든 화면은 같은 게시판 원본, 이름, 순서를 사용한다.
- 데스크톱의 펼친 목록과 모바일의 선택 상자는 표현만 다르고 선택 결과와 주소 규칙은 같다.
- 목록·검색에서는 `전체글보기`를 제공하고, 글쓰기에서는 실제 게시판 하나를 반드시 선택한다.
- 선택한 게시판은 `board` 주소 매개변수로 표현해 새로고침하거나 링크를 공유해도 같은 게시판이 열린다.
- 즐겨찾는 게시판은 계정별로 저장하며 현재 선택을 나타내는 `board` 주소와 독립적으로 추가·해제한다.
- 즐겨찾기는 목록 앞에 노출하되, 즐겨찾기끼리와 나머지 게시판끼리는 각각 원본 게시판 순서를 유지한다.
- 홈의 즐겨찾는 게시판 바로가기도 같은 계정별 목록을 사용한다.

## 프로필과 개인정보 최소화

- 모든 계정은 성별·연령을 추정하게 하지 않는 중립적인 기본 아바타로 시작한다.
- 회원가입 또는 프로필 수정에서 본인이 사진을 올린 경우에만 해당 사진을 표시한다.
- 가입 사진은 선택 입력이며 JPG, PNG, WEBP만 받는다. 서버에서 실제 파일 시그니처와 2MB 제한을 다시 확인하고, 사진 저장 실패만으로 이미 완료된 계정을 되돌리지 않는다.
- 접속 여부, 마지막 활동 시각, `활동 중` 같은 실시간 상태를 공개 프로필과 댓글에 표시하지 않는다.
- 댓글에는 대화에 필요한 닉네임, 작성 시각, 글쓴이 여부만 우선 표시한다.

## 모델 데이터

사용자가 목록에 없는 모델을 직접 입력하거나 모델명을 모르면 임시 모델로 다룬다. 관리자가 기존 모델과 연결하거나 새 모델로 승인하기 전에는 검증된 카탈로그를 자동 변경하지 않는다. 병합 시 질문과 댓글 이력은 유지한다.

## 안전과 운영

- 공개 글에 주소, 전화번호, 송장, 얼굴 등 개인정보를 올리지 않도록 안내한다.
- 감전, 화재, 배터리 팽창 위험이 있으면 직접 분해보다 사용 중단을 먼저 안내한다.
- 신고된 내용은 숨김과 삭제를 구분하고 운영 이력을 남긴다.
- 관리자 상태와 전문가 인증 상태는 본인이 임의로 변경할 수 없다.
- MVP에서는 결제와 정산을 제공하지 않으며, 수리 요청은 수락·거절 흐름까지만 검증한다.
